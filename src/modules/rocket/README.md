# rocket

3D-ракета на фоне всей страницы, которая летит по скроллу.

| Файл | Что делает |
| --- | --- |
| `flight.js` | Чистая логика траектории: таблица `WAYPOINTS`, `buildFlightTimeline`, `sampleFlight`, перевод в мир `toWorld`, тяга от скорости `thrustWithVelocity`, проверка перекрытия экрана `coversViewport`. |
| `particles.js` | `ParticlePool` — частицы выхлопа на типизированных массивах без аллокаций; `spawnBudget` — сколько частиц родить за кадр независимо от FPS. |
| `rocket.scene.js` | Three-сцена: модель ракеты (Lathe-корпус, стабилизаторы, иллюминатор, 2 ускорителя), факел на шейдере, свет факела, частицы, звёзды с параллаксом, стартовая площадка. |
| `rocket.glsl.js` | Шейдеры факела, частиц и звёзд. |
| `index.js` | Подключение к странице: путевые точки из `[data-flight]`, события шины, пауза под `[data-occlude]`. |

## Сценарий полёта

1. **`hero`**: ракета стоит на площадке.
2. **`manifesto` → `story` → `apogee`**: взлёт и набор высоты.
3. **`orbit`**: разворот на 180° (огонь сверху, нос вниз), ракета идёт вниз.
4. **`dive` → `exit`**: спускаясь, уходит за правый край экрана перед слайдерами (`x > 1`).
5. **Слайдеры, вода, архив**: секции непрозрачны, ракета не видна и не рисуется.
6. **`return` → `mission`**: возвращается справа, всё ещё носом вниз.
7. **`landing`**: разворачивается (крен 180° → 360°, в ту же сторону) и садится на станцию, площадка поднимается навстречу.

Звёзды бегут против направления носа (`heading(roll)`): при подъёме они едут вниз, при спуске носом вниз вверх. Искры выхлопа летят по оси сопла, куда бы ни смотрела ракета.

## Как устроен полёт

1. Каждый элемент с `data-flight="id"` получает ScrollTrigger. По умолчанию `start: 'top 65%'`, но опорную линию можно задать отдельно: `data-flight-start="top bottom"`. Для промежуточных точек внутри секций используются невидимые маркеры `<i class="flight-marker" data-flight="…">`.
2. После каждого `refresh` (в том числе после пинов) `start` триггеров становятся позициями путевых точек. Они прижимаются к `[0, maxScroll]`: точка посадки стоит в самом низу страницы.
3. В каждом кадре `sampleFlight(timeline, scroll)` интерполирует состояние между соседними точками (`smoothstep`), а `toWorld` переводит доли экрана в мир (при `|x| > 1` ракета не прижимается к краю).
4. Тяга = тяга точки + бонус от скорости прокрутки.

Чтобы добавить точку, допишите `id` в `WAYPOINTS` и поставьте `data-flight="id"` на секцию или маркер.

## События шины

| Событие | Эффект |
| --- | --- |
| `story:scene` (номер сцены) | С `SEPARATION_SCENE` и дальше ускорители отстреливаются, при прокрутке назад возвращаются. |
| `launch` | Всплеск тяги, дрожь и поток искр. |

## Производительность

- Пиксельная плотность, число звёзд и частиц зависят от `getQuality()`.
- Сцена не рисуется, пока экран полностью закрыт секциями с `data-occlude` (учитывается и их объединение на стыке).
- three загружается отдельным чанком.

## Перенос в другой проект

- **Файлы:** вся папка `rocket/` + `core/env.js`, `core/lifecycle.js`, `core/webgl.js`, `core/math.js`, `core/rng.js`; canvas `.rocket-canvas` вне ScrollSmoother; секции-путевые точки с `data-flight`.
- **GSAP:** ScrollTrigger (только измерение позиций) + three.js.
- Сцена (`rocket.scene.js`) не зависит от GSAP и прокрутки — её можно взять отдельно и управлять своими числами (например, в React Three Fiber или в игре).

Общий порядок переноса и примеры для React/Vue/Next — `docs/06-porting.md`.
