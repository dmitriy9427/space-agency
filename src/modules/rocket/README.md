# rocket

3D-ракета на фоне всей страницы, которая летит по скроллу.

| Файл | Что делает |
| --- | --- |
| `flight.js` | Чистая логика траектории: таблица `WAYPOINTS`, `buildFlightTimeline`, `sampleFlight`, перевод в мир `toWorld`, тяга от скорости `thrustWithVelocity`, проверка перекрытия экрана `coversViewport`. |
| `particles.js` | `ParticlePool` — частицы выхлопа на типизированных массивах без аллокаций; `spawnBudget` — сколько частиц родить за кадр независимо от FPS. |
| `rocket.scene.js` | Three-сцена: модель ракеты (Lathe-корпус, стабилизаторы, иллюминатор, 2 ускорителя), факел на шейдере, свет факела, частицы, звёзды с параллаксом, стартовая площадка. |
| `rocket.glsl.js` | Шейдеры факела, частиц и звёзд. |
| `index.js` | Подключение к странице: путевые точки из `[data-flight]`, события шины, пауза под `[data-occlude]`. |

## Сценарий полёта

Крен (`roll`): 0 — нос вверх, 90 — влево, 180 — вниз, 270 — вправо. По таблице он только растёт
(0 → 720): один непрерывный разворот против часовой стрелки.

| # | Точки | Что делает ракета | Где в разметке |
| --- | --- | --- | --- |
| 1 | `hero` | стоит на площадке | секция hero |
| 2 | `manifesto` → `turn` → `flip` | чуть взлетает, по дуге уходит влево, разворачивается | манифест + два маркера |
| 3 | `story` → `apogee` | летит носом вниз, пока идёт закреплённая история | история, верх «Орбиты» |
| 4 | `orbit` → `bank` → `dive` → `exit` | доворачивает нос вправо и уходит за правый край | «Орбита» + три маркера на долях её высоты |
| 5 | — | слайдеры, вода, архив непрозрачны: ракета не видна и не рисуется | `data-occlude` |
| 6 | `return` → `glide` | вылетает справа носом влево | «окно в небо» `.approach` перед подвалом |
| 7 | `mission` → `final` | нос поворачивается вниз, ракета немного пролетает | подвал + маркер |
| 8 | `landing` | разворачивается носом вверх и садится на площадку | низ страницы |

`.approach` — пустой экран со звёздами между архивом и подвалом. Без него возвращение ракеты
было бы скрыто непрозрачным архивом: манёвру негде было бы происходить.

Звёзды бегут против направления носа (`heading(roll)`): при подъёме они едут вниз, при спуске носом вниз вверх. Искры выхлопа летят по оси сопла, куда бы ни смотрела ракета.

## Как устроен полёт

1. Каждый элемент с `data-flight="id"` получает ScrollTrigger. По умолчанию `start: 'top 65%'`, но опорную линию можно задать отдельно: `data-flight-start="top bottom"`. Для промежуточных точек внутри секций используются невидимые маркеры `<i class="flight-marker" data-flight="…">`.
2. После каждого `refresh` (в том числе после пинов) `start` триггеров становятся позициями путевых точек. Они прижимаются к `[0, maxScroll]`: точка посадки стоит в самом низу страницы.
3. В каждом кадре `sampleFlight(timeline, scroll)` интерполирует состояние между соседними точками (`smoothstep`), а `toWorld` переводит доли экрана в мир. Горизонталь не прижимается к краю экрана: раньше `x` до 1 зажимался в 0.9, а после 1 — нет, и на уходе за экран ракета делала рывок.
4. Тяга = тяга точки + бонус от скорости прокрутки.

Чтобы добавить точку, допишите `id` в `WAYPOINTS` и поставьте `data-flight="id"` на секцию или маркер.

## События шины

| Событие | Эффект |
| --- | --- |
| `story:scene` (номер сцены) | С `SEPARATION_SCENE` и дальше ускорители отстреливаются, при прокрутке назад возвращаются. |
| `launch` | Кнопка «Пуск»: всплеск тяги; пока страница едет наверх, ракета идёт по сценарию **в обратную сторону, носом вверх**. |
| `launch:arrived` | Страница доехала наверх: управление снова у обычного сценария. |
| `launch:aborted` | Пользователь сам взялся за прокрутку: нос за 1,2 с возвращается к сценарию. |

## Запуск по кнопке «Пуск»

Ракета **не улетает за кадр**. После отсчёта подвал плавно везёт страницу наверх
(`RETURN_DURATION` в `mission/index.js`), а положение ракеты, как всегда, считается от
прокрутки — поэтому она проходит тот же путь в обратном порядке и садится на стартовую
площадку первого экрана. Меняется только нос (`returnState` в `flight.js`):

- по вертикали нос всегда вверх (по сценарию вниз → обратно вверх);
- на боковых участках — наклон `LAUNCH.lean` в сторону движения: где ракета улетала носом
  вправо, обратно она возвращается с наклоном влево;
- тяга не ниже `LAUNCH.thrust`.

`mix` (1 → 0) плавно возвращает нос к сценарию — в конце полёта и если пользователь
перехватил прокрутку. На обеих площадках нос и так вверх, поэтому включение и отпускание —
без скачка. При `prefers-reduced-motion` страница просто оказывается наверху.

## Производительность

- Пиксельная плотность, число звёзд и частиц зависят от `getQuality()`.
- Сцена не рисуется, пока экран полностью закрыт секциями с `data-occlude` (учитывается и их объединение на стыке).
- three загружается отдельным чанком.

## Перенос в другой проект

- **Файлы:** вся папка `rocket/` + `core/env.js`, `core/lifecycle.js`, `core/webgl.js`, `core/math.js`, `core/rng.js`; canvas `.rocket-canvas` вне ScrollSmoother; секции-путевые точки с `data-flight`.
- **GSAP:** ScrollTrigger (только измерение позиций) + three.js.
- Сцена (`rocket.scene.js`) не зависит от GSAP и прокрутки — её можно взять отдельно и управлять своими числами (например, в React Three Fiber или в игре).

Общий порядок переноса и примеры для React/Vue/Next — `docs/06-porting.md`.
