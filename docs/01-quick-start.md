# 1. Быстрый старт

## Что нужно установить

- **Node.js 20+** (проверено на 24). Это среда, в которой работают сборщик и тесты.
  Проверить: `node -v`.
- **npm** — менеджер пакетов, ставится вместе с Node.js.

## Команды

```bash
npm install        # скачать зависимости (один раз)
npm run dev        # запустить сайт для разработки → http://localhost:5173
npm test           # прогнать все тесты один раз
npm run test:watch # тесты в режиме наблюдения: перезапускаются при сохранении файла
npm run coverage   # тесты + отчёт о покрытии (папка coverage/)
npm run build      # собрать готовый сайт в папку dist/
npm run preview    # посмотреть собранный dist/ локально
```

`npm run dev` запускает **Vite** — инструмент, который отдаёт файлы проекта браузеру и
перезагружает страницу при каждом сохранении (это называется HMR, hot module replacement).

### Режим отладки

Добавьте к адресу `?debug`: `http://localhost:5173/?debug`. В левом нижнем углу появится
счётчик: кадры в секунду (FPS), самый долгий кадр и сколько раз за кадр ракета обращается к
видеокарте (draw calls), либо «ракета спит», если её сейчас не видно и она не рисуется.

В консоли браузера будет доступен объект `window.__orbita` — через него можно заглянуть в
состояние: `__orbita.ctx.rocket.state` — где сейчас ракета, `__orbita.app.mounted` — какие
модули запустились.

## Что где лежит

```
space-agency/
├── index.html            ← главная: секции, тексты, атрибуты data-*
├── missions.html         ← страница «Миссии»
├── destinations.html     ← страница «Направления»
├── public/
│   ├── photos/           ← 30 фото NASA (p01.jpg … p32.jpg)
│   └── favicon.svg
├── src/
│   ├── main.js           ← точка входа: шрифты, стили, СПИСОК МОДУЛЕЙ
│   ├── app.js            ← приложение: общий слой, страницы, переходы между ними
│   ├── core/             ← «ядро»: общие инструменты, не знающие про конкретные секции
│   │   ├── gsap.js       ← регистрация всех плагинов GSAP (один раз на всё приложение)
│   │   ├── registry.js   ← находит data-module в HTML и запускает нужный код
│   │   ├── router.js     ← перехват ссылок, загрузка страниц без перезагрузки

│   │   ├── bus.js        ← шина событий: модули общаются, не зная друг о друге
│   │   ├── env.js        ← reduced motion, тач-экран, WebGL, уровень качества

│   │   └── fps.js        ← счётчик кадров для ?debug
│   ├── content/          ← ДАННЫЕ: фото, видео, миссии, планеты + шаблоны карточек
│   ├── modules/          ← ЭФФЕКТЫ: по папке на секцию / эффект
│   │   ├── rocket/       ← 3D-ракета, летящая по скроллу
│   │   ├── hero/         ← первый экран
│   │   ├── manifesto/    ← абзац + счётчики
│   │   ├── story/        ← закреплённая история из 4 сцен
│   │   ├── orbit/        ← SVG: орбита, спутник, морфинг
│   │   ├── sliders/      ← 6 слайдеров (ring, stack, infinite, video-strip, shader)
│   │   ├── liquid/       ← водная гладь (симуляция волн на GPU)
│   │   ├── gallery/      ← бесконечный архив фото
│   │   ├── mission/      ← подвал: терминал, отсчёт, пуск
│   │   ├── cursor/       ← неоновый курсор + магнитные кнопки
│   │   ├── nav/          ← шапка
│   │   ├── page-transition/ ← «занавес» при переходе между страницами
│   │   ├── page-intro/, hscroll/, flip-filter/ ← модули страницы «Миссии»
│   │   └── fullscreen-slides/ ← страница «Направления»
│   └── styles/           ← CSS: base, sections, sliders, effects, pages
├── test/                 ← настройка тестов и помощники

├── CREDITS.md            ← авторство фото и видео
```

**Правило проекта:** в `core/` лежит только то, что можно взять в любой другой проект без
изменений. Всё, что относится к конкретной секции, — в `modules/<имя>/`.

## Как страница «оживает»: шаг за шагом

Это самое полезное, что стоит понять в начале. Вот что происходит после того, как браузер
открыл страницу:

1. **Браузер читает `index.html`** и строит обычную статическую страницу: тексты, заголовки,
   пустые контейнеры для карточек. Анимаций ещё нет. Если JavaScript отключён, страница всё
   равно читается.

2. **Загружается `src/main.js`.** Он подключает шрифты и CSS (Vite превращает `import
   './styles/base.css'` в обычный `<link>`), потом вызывает функцию `start()`.

3. **`start()` узнаёт окружение** (`core/env.js`):
   - просил ли пользователь меньше анимаций (`prefers-reduced-motion`);
   - насколько мощное устройство (`getQuality()` → `low` / `medium` / `high`).

4. **Заполняются повторяющиеся карточки** (`renderSlots()` из `content/render.js`). В HTML
   стоит пустой `<div data-render="ring" data-photos="p01,p05,…">`, а функция-шаблон кладёт
   в него карточки с фото. Так одна карточка описана один раз, а не скопирована восемь раз.

5. **Создаётся плавный скролл** (ScrollSmoother), если это не телефон и не reduced motion.
   Дальше всё это делает `src/app.js`.

6. **Собирается общий «контекст» `ctx`** — объект, который получит каждый модуль:
   ```js
   ctx = { gsap, bus, quality, reduced, smoother, getScroll }
   ```

7. **Запускаются модули** (`mountModules` из `core/registry.js`): сначала общие (курсор,
   шапка), потом модули текущей страницы. Он находит в HTML все элементы с
   `data-module="имя"` и для каждого вызывает функцию `init(элемент, ctx)` из
   соответствующего модуля. Модуль вешает обработчики событий, создаёт анимации и
   возвращает объект с методом `destroy()` — «как убрать за собой».

8. **ScrollTrigger пересчитывает позиции** (`ScrollTrigger.refresh()`). Модули создавали
   закреплённые секции (пины) в разное время, и после этого нужно один раз всё измерить
   заново. Ещё раз то же самое делается, когда загрузятся шрифты — от шрифта зависит высота
   текста, а значит, и все позиции.

9. **Дальше всё работает само.** Каждый кадр (60–120 раз в секунду) GSAP вызывает свой
   «тикер»: двигает твины, обновляет анимации, привязанные к скроллу, а WebGL-сцены
   рисуют новый кадр — но только те, что сейчас видны.

## Переход на другую страницу

Клик по ссылке «Миссии» не перезагружает страницу. Роутер (`src/core/router.js`) скачивает
HTML новой страницы, «занавес» (`modules/page-transition`) закрывает экран, под ним модули
старой страницы убираются (`destroy`), содержимое `<main data-page>` подменяется, модули
новой страницы запускаются, и занавес уходит. Шапка, курсор, небо и плавный скролл при этом
не пересоздаются. Подробно — [04-architecture.md](04-architecture.md).

## Первое упражнение

Чтобы почувствовать проект, откройте `src/modules/rocket/flight.js` и найдите таблицу
`WAYPOINTS`. Поменяйте у `hero` значение `x: 0.46` на `x: -0.5` и сохраните. Ракета на
первом экране переместится влево. Это и есть главный приём проекта: **поведение задаётся
данными (числами в таблице), а код только читает эти данные**.
