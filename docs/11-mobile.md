# 11. Мобильная версия: что и где доработать

**Сейчас сайт сделан для компьютера.** На телефоне он открывается и в целом работает, но часть
эффектов упрощена или неудобна, а меню нет. На узких экранах показывается плашка «Сайт пока
сделан для компьютера…».

Все места, которые нужно доработать, помечены в коде комментарием **`МОБИЛКА:`**. Найти их
все:

```bash
grep -rn "МОБИЛКА" src index.html missions.html destinations.html
```

Ниже — тот же список, сгруппированный по задачам, в рекомендуемом порядке.

## 1. Навигация (обязательно)

| Где | Что сейчас | Что сделать |
| --- | --- | --- |
| `src/styles/base.css` (`.nav__links`, медиазапрос 860px) | меню просто прячется | кнопка-«бургер» + выезжающее меню (анимация — GSAP timeline) |
| все HTML — `.desktop-note` + стили в `base.css` | плашка «пока для компьютера» | удалить, когда мобильная версия готова |

## 2. Высота экрана

| Где | Что сделать |
| --- | --- |
| `src/styles/sections.css` (`.story__pin`) и другие `100vh` | на телефоне `100vh` не учитывает адресную строку → `100svh` (с `100vh` как запасным значением строкой выше) |

## 3. Жесты: не мешать прокрутке страницы

Главное правило: на телефоне вертикальный свайп — это прокрутка страницы. Если эффект его
перехватывает, человек «застревает». В CSS это решает `touch-action`: `pan-y` — «вертикальные
жесты отдай странице».

| Модуль | Где | Проблема | Решение |
| --- | --- | --- | --- |
| Стопка | `sliders.css` (`.stack__deck`), `sliders/stack/index.js` | `touch-action: none` — со стопки нельзя прокрутить страницу | `pan-y` + Draggable `type: 'x'` |
| Шейдерный слайдер | `sliders.css` (`.shader-slider__stage`), `sliders/shader/index.js` | вертикальные свайпы листают слайды вместо страницы | оставить только горизонтальные (`pan-y`) или закрепить слайдер на весь экран (pin) |
| Вода | `effects.css` (`.liquid__stage`), `liquid/index.js` | палец рисует рябь и одновременно крутит страницу | только тап (капля) и дождь, без рисования пальцем |
| Галерея | `gallery/index.js`, `effects.css` | размеры черновые | проверить размеры, выключить наклон (`tilt: 0`) |

## 4. Наведение (hover) — на телефоне его нет

| Модуль | Где | Решение |
| --- | --- | --- |
| Видеолента | `sliders/video-strip/index.js` (ветка «МОБИЛКА» в `onClick`), `sliders.css` (`--vstrip-card-width`) | раскрытие по тапу уже есть; уменьшить ширину карточек (~180px), проверить автозапуск видео |
| Курсор | `cursor/index.js` | на тач-экранах уже выключен — ничего делать не нужно |

## 5. Размеры и раскладка

| Где | Что сделать |
| --- | --- |
| `sliders.css` (`.ring__card`) | кольцо из 8 карточек мелкое — меньше карточек или крупнее |
| `pages.css` (`--hscroll-card`) | карточка миссии ~78vw |
| `pages.css` (`.fslide__title`, `.route`) | заголовки меньше, мини-схему спрятать |
| `sections.css` (медиазапрос истории) | черновая раскладка: текст внизу — проверить с ракетой |

## 6. Ракета и производительность

| Где | Что сделать |
| --- | --- |
| `rocket/flight.js` (`toWorld`) | для портрета — своя таблица `WAYPOINTS` (ракета меньше и не поверх текста) |
| `core/env.js` (`getQuality`, `isCoarsePointer`) | телефоны получают уровень качества пониже; проверить FPS на реальном телефоне |
| `src/app.js` | ScrollSmoother на тач-экранах уже выключен (так и задумано) |

## Как тестировать мобильную версию

1. DevTools → Toggle device toolbar (Ctrl/Cmd + Shift + M) → iPhone/Android, **перезагрузить
   страницу** (часть проверок — один раз при загрузке).
2. Обязательно на реальном телефоне: эмуляция не показывает настоящую производительность и
   поведение адресной строки. Vite: `npm run dev -- --host` → откройте с телефона адрес
   `http://<ip-компьютера>:5173`.
