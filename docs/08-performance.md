# 8. Производительность: почему не тормозит

Замер проекта (Chrome, MacBook, окно 1440×900, плотность пикселей 2): **120 кадров в секунду
во всех секциях, самый долгий кадр около 10 мс.** Ниже — приёмы, за счёт которых это
получилось. Они универсальны: применяйте их в любом проекте с анимациями.

## Как измерить

1. **`?debug`** в адресе: FPS, худший кадр, draw calls ракеты.
2. **DevTools → Performance → Record**, покрутите страницу, Stop. Ищите красные «длинные
   задачи» (> 50 мс) и жёлтые блоки «Recalculate Style / Layout» внутри кадров.
3. **DevTools → Rendering → Frame Rendering Stats** — счётчик кадров поверх страницы.
4. **Проверяйте в видимой вкладке.** Фоновые вкладки и скрытые панели браузер ограничивает
   (до 1 кадра в секунду) — замеры там ничего не значат.
5. Проверьте на слабом ноутбуке или включите в DevTools → Performance «CPU: 4× slowdown».

## Приёмы

### 1. Не работать, когда не видно

- Каждый WebGL-цикл, лента, галерея — только пока секция на экране (`onViewport` в
  `core/lifecycle.js`).
- Ракета не рисуется, пока экран целиком закрыт непрозрачными секциями (`data-occlude` →
  `coversViewport`).
- Курсор, ленты, галерея — засыпают, когда ничего не движется (флаги `drawing`, `dirty`,
  `engine.step()` → false).

### 2. Двигать только `transform` и `opacity`

Они не запускают пересчёт раскладки (Layout) — см. [02-concepts.md, 2.3](02-concepts.md).
Исключения в проекте осознанные и дешёвые: ширина 2 карточек видеоленты, высота сетки
фильтра (один элемент).

### 3. Не создавать мусор в кадре

Частицы — в заранее выделенных массивах (`ParticlePool`), объекты переиспользуются
(`quickTo` вместо нового твина на каждое движение мыши).

### 4. Ограничить плотность пикселей

На Retina-экране canvas с плотностью 3 — это в 9 раз больше пикселей, чем при 1. Разница
на глаз почти незаметна, а нагрузка огромная. `getQuality()` ограничивает плотность 2
(мощные устройства), 1.5, 1; полноэкранные шейдеры — не больше 1.5.

### 5. Ленивая загрузка

- three.js (~570 КБ) — отдельным файлом, только когда нужна WebGL-сцена (динамический
  `import()`).
- Фото — `loading="lazy"`: грузятся, только подъезжая к экрану.
- Видео — `preload="none"` и `src` только при первом раскрытии карточки.

### 6. Один цикл на всё

Все анимации — на одном тикере GSAP (`gsap.ticker`), а не в десятке своих
`requestAnimationFrame`.

### 7. Экономить WebGL-контексты

Их у браузера около 16. Каждая сцена в `destroy()` вызывает `releaseRenderer` (сразу отдаёт
контекст). Это особенно важно при переходах между страницами.

### 8. Симуляции — в маленьком разрешении

Вода считается в текстуре 160–288 px по меньшей стороне, а выводится на весь экран с
плавной интерполяцией — глаз разницы не видит.
