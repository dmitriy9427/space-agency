# 3. Плагины GSAP: что, где, как

С версии 3.13 GSAP и **все его плагины бесплатны** и лежат в обычном пакете `gsap`
(`npm i gsap`). Плагин — это дополнение к ядру GSAP, которое нужно один раз
«зарегистрировать»:

```js
import { gsap } from 'gsap'
import { ScrollTrigger } from 'gsap/ScrollTrigger'

gsap.registerPlugin(ScrollTrigger)
```

В проекте регистрация всех плагинов собрана в одном файле — `src/core/gsap.js`. Остальной
код импортирует GSAP **только оттуда**: `import { gsap, Flip } from '../../core/gsap.js'`.
Так плагины гарантированно зарегистрированы до первого использования, а в тестах этот файл
можно подменить.

Ниже — каждый плагин: что делает, где используется в проекте, минимальный пример и
подводные камни. Официальная документация: [gsap.com/docs/v3](https://gsap.com/docs/v3/).

| Плагин | Для чего | Где в проекте |

Плюс из ядра GSAP: `gsap.quickTo` (курсор), `gsap.context` (уборка во всех модулях),
`gsap.ticker` (все циклы).

## ScrollTrigger

**Что делает.** Связывает анимацию с прокруткой: запускает её, когда элемент доезжает до
нужного места, ведёт её прогресс скроллом (`scrub`) или закрепляет секцию (`pin`).
Подробное объяснение понятий — в [02-concepts.md](02-concepts.md#25-анимации-от-скролла-scrolltrigger).

**Где в проекте.**
- `modules/story/index.js` — `pin` + `scrub`: секция стоит, скролл проигрывает 4 сцены.
- `modules/orbit/index.js` — то же для SVG.
- `modules/gallery/index.js` — `pin` + `onUpdate`: прокрутка двигает сетку.
- `modules/manifesto/index.js` — `scrub` (слова загораются) и `once` (счётчики).
- `modules/rocket/index.js` — триггеры без анимации, только чтобы **измерить**, на какой
  позиции прокрутки каждая секция доходит до опорной линии.

```js
gsap.timeline({
  scrollTrigger: { trigger: '.story', pin: true, start: 'top top', end: '+=300%', scrub: 0.8 },
})
  .to('.scene-1', { opacity: 0 })
  .from('.scene-2', { opacity: 0 })
```

### Горизонтальный скролл: `containerAnimation`

Лента миссий (`modules/hscroll`): секция закреплена, вертикальная прокрутка двигает ряд
карточек вбок. Для анимаций карточек внутри ленты используется
`scrollTrigger: { containerAnimation: главныйТвин, start: 'left 80%' }` — «считай положение
карточки внутри горизонтального движения». У главного твина обязательно `ease: 'none'`.
Подробно — README модуля `hscroll`.

**Подводные камни.**
- После изменения высоты страницы (шрифты, картинки, новый контент) вызывайте
  `ScrollTrigger.refresh()`.
- Пины, созданные не по порядку сверху вниз, путают расчёты: после создания вызывайте
  `ScrollTrigger.sort()` (так сделано в `main.js`) или задавайте `refreshPriority`.
- Не анимируйте с ScrollTrigger сам закрепляемый элемент — анимируйте его детей.
- При отладке включайте `markers: true`.

## ScrollSmoother

**Что делает.** Плавная инерционная прокрутка и параллакс через атрибуты `data-speed`,
`data-lag`. Требует разметку `#smooth-wrapper > #smooth-content`. Подробно — в
[02-concepts.md](02-concepts.md#26-плавный-скролл-scrollsmoother).

**Где в проекте.** `src/main.js` (создание), `index.html` (обёртки, `data-speed` у
характеристик ракеты на первом экране, `data-lag` у счётчиков).

```js
ScrollSmoother.create({ wrapper: '#smooth-wrapper', content: '#smooth-content', smooth: 1.1, effects: true })
```

**Подводные камни.**
- `position: fixed` внутри `#smooth-content` не работает — выносите фиксированные элементы
  наружу.
- Текущая прокрутка — `smoother.scrollTop()`, а не `window.scrollY` (в проекте это
  `ctx.getScroll()`).
- Прокрутка к элементу — `smoother.scrollTo(el, true)`.
- На тач-устройствах часто лучше выключить (в проекте так и сделано).

## ScrollToPlugin

**Что делает.** Плавно прокручивает окно или блок к позиции или элементу.

**Где в проекте.** `modules/nav/index.js` — клики по ссылкам меню, когда ScrollSmoother
выключен (телефон, reduced motion).

```js
gsap.to(window, { scrollTo: { y: '#fleet', autoKill: true }, duration: 1.2, ease: 'power3.inOut' })
```

`autoKill: true` — если пользователь сам начал крутить колесо, прокрутка прерывается.

## SplitText

**Что делает.** Режет текст на `chars` (буквы), `words` (слова), `lines` (строки), оборачивая
каждую часть в `<div>`. После этого каждую букву можно анимировать отдельно.

**Где в проекте.**
- `modules/hero/index.js` — буквы заголовка выезжают снизу из-под «маски».
- `modules/manifesto/index.js` — слова загораются по скроллу.
- `modules/sliders/shader/index.js` — заголовок слайда меняется по буквам.

```js
const split = SplitText.create('.title', { type: 'chars, words', mask: 'chars' })
gsap.from(split.chars, { yPercent: 115, stagger: 0.035, ease: 'expo.out' })
// ...
split.revert() // вернуть исходный текст
```

`mask: 'chars'` оборачивает каждую букву ещё в один контейнер с `overflow: clip` — буква
«выезжает из-под пола», а не появляется в воздухе.

**Подводные камни.**
- Режьте после загрузки шрифтов, иначе ширины букв будут от запасного шрифта (в версиях
  3.13+ есть `autoSplit: true`, который перерезает сам).
- Всегда вызывайте `revert()` при уборке (внутри `gsap.context` это делается
  автоматически).
- `type: 'words'` безопаснее для длинных абзацев: тысяча `<div>`-букв нагружает страницу.

## ScrambleTextPlugin

**Что делает.** Анимирует текст через «перебор» случайных символов, пока не проявится
нужный — эффект «расшифровки».

**Где в проекте.** Надпись над заголовком первого экрана, подписи цифр в манифесте,
обратный отсчёт «T−05 … ПУСК» в подвале.

```js
gsap.to(el, { duration: 1.2, scrambleText: { text: 'ПУСК', chars: '0123456789', speed: 1 } })
```

`chars` — из каких символов перебирать: `'upperCase'`, `'lowerCase'`, `'01'` или своя строка.

## TextPlugin

**Что делает.** Меняет текст элемента, «допечатывая» его по одной букве.

**Где в проекте.** `modules/mission/index.js` — журнал пуска в терминале печатается строка
за строкой.

```js
gsap.to(line, { text: { value: '> телеметрия ... OK' }, duration: 1, ease: 'none' })
```

`ease: 'none'` — печать с постоянной скоростью; длительность в проекте пропорциональна
длине строки.

## Draggable

**Что делает.** Делает элемент перетаскиваемым мышью и пальцем: `type: 'x'`, `'y'`,
`'x,y'`, `'rotation'`. Даёт события `onPress`, `onDrag`, `onRelease`, `onThrowUpdate` и
текущие `this.x`, `this.y`.

**Где в проекте.**
- `modules/sliders/ring/index.js` — тянем **невидимый прокси**-элемент, а его `x`
  переводим в угол поворота кольца. Приём «прокси» нужен, когда двигать надо не сам элемент,
  а что-то другое (угол, прогресс, позицию в 3D).
- `modules/sliders/stack/index.js` — тянем саму верхнюю карточку в обе стороны.

```js
const proxy = document.createElement('div')
Draggable.create(proxy, {
  type: 'x',
  trigger: '.ring-stage',                       // за что хватать
  onDrag() { ring.rotation = this.x * 0.22 },   // x прокси → градусы
})
```

**Подводные камни.** Добавьте элементу `touch-action: pan-y` в CSS, иначе на телефоне
вертикальный свайп будет не прокручивать страницу, а тащить слайдер.

## InertiaPlugin

**Что делает.** Продолжает движение после броска с затуханием и умеет «доводить» до
ближайшего допустимого значения (`snap`). Обычно используется вместе с Draggable
(`inertia: true`). Также даёт `InertiaPlugin.getVelocity(el, 'x')`.

**Где в проекте.** 3D-кольцо: бросили — кольцо докручивается до ближайшей карточки.

```js
Draggable.create(proxy, {
  type: 'x',
  inertia: true,
  snap: { x: (value) => Math.round(value / step) * step }, // куда доводить
})
```

## Observer

**Что делает.** Одно API для всех способов «двигать»: мышь, палец, колесо, скролл. Сообщает
дельты (`deltaX`), скорость (`velocityX`), направление, ось (`lockAxis`). Сам **ничего не
двигает** — вы решаете, что делать с этими числами.

**Где в проекте.** Бесконечная лента (`sliders/infinite`), шейдерный слайдер
(`sliders/shader`) и галерея (`gallery`) — там, где движение считает свой движок (пружина,
инерция), а от жеста нужны только числа.

```js
Observer.create({
  target: el,
  type: 'pointer,touch',
  dragMinimum: 4,         // до 4 px — это ещё клик, а не перетаскивание
  lockAxis: true,         // начал вбок — дальше только вбок (не мешаем вертикальному скроллу)
  onDrag: (self) => engine.drag(self.deltaX),
  onRelease: (self) => engine.release(self.velocityX),
})
```

**Чем отличается от Draggable.** Draggable двигает элемент сам (и добавляет `transform`).
Observer только сообщает о жесте. Если у вас своя физика — берите Observer.

**Подводные камни.** По умолчанию Observer группирует события до следующего кадра
(`debounce`) — в тестах это видно (см. [09-testing.md](09-testing.md)).

## Flip

**Что делает.** Анимирует то, что обычно анимировать нельзя: перенос элемента в другой
родитель, смену класса, смену порядка, `display`. Принцип First → Last → Invert → Play
подробно разобран в начале `src/modules/gallery/lightbox.js`.

**Где в проекте.**
- Лайтбокс архива (`gallery/lightbox.js`): та же самая картинка переносится из ячейки сетки
  в окно на весь экран, Flip анимирует путь.
- Фильтр снимков на «Миссиях» (`flip-filter`): скрыли лишние карточки (`display: none`),
  Flip плавно переставил оставшиеся (`onEnter`/`onLeave` — появление/исчезновение).

```js
const state = Flip.getState(img)            // 1. запомнить, где сейчас
modal.appendChild(img)                      // 2. мгновенно переместить
Flip.from(state, { duration: 0.8, scale: false, absolute: true }) // 3-4. анимировать путь
```

`scale: false` — менять реальные `width/height`, а не растягивать масштабом (картинка не
искажается). `absolute: true` — на время анимации вынуть элемент из потока, чтобы соседи
не прыгали.

**Подводные камни.** После анимации Flip может оставить инлайн-стили — снимайте их
`gsap.set(el, { clearProps: 'all' })`, если элемент возвращается в обычную вёрстку.

## DrawSVGPlugin

**Что делает.** Анимирует видимую часть линии SVG (`stroke`): «0% 0%» — не видно,
«0% 100%» — нарисована целиком, «40% 60%» — только середина.

**Где в проекте.** `modules/orbit/index.js` — эллипс орбиты прорисовывается по скроллу.

```js
gsap.fromTo('#orbit', { drawSVG: '0% 0%' }, { drawSVG: '0% 100%', scrollTrigger: { scrub: true } })
```

**Подводные камни.** Работает с `stroke` (обводкой), у элемента должен быть `stroke` и
обычно `fill: none`.

## MorphSVGPlugin

**Что делает.** Плавно перетекает одну SVG-фигуру в другую, даже если у них разное число
точек.

**Где в проекте.** Орбита: круг-планета → звезда → луна → силуэт ракеты. Целевые фигуры
лежат невидимо в `<defs>` и указаны в атрибуте `data-morph-to`.

```js
gsap.to('#shape', { morphSVG: { shape: '#star', type: 'rotational' }, duration: 0.6 })
```

`type: 'rotational'` даёт более «органичное» перетекание (точки вращаются, а не едут по
прямой).

## MotionPathPlugin

**Что делает.** Ведёт элемент по кривой (SVG-путь или массив точек), может поворачивать
его по направлению движения.

**Где в проекте.** Спутник летит по той же орбите, которую рисует DrawSVG.

```js
gsap.to('#satellite', {
  motionPath: { path: '#orbit', align: '#orbit', alignOrigin: [0.5, 0.5], autoRotate: 90 },
})
```

`align` — совместить систему координат элемента с путём; `alignOrigin: [0.5, 0.5]` — за
какую точку элемента «держаться» (центр); `autoRotate: 90` — поворачивать вдоль пути с
поправкой 90°.

## Physics2DPlugin

**Что делает.** Анимирует полёт по законам физики: начальная скорость, угол, гравитация,
трение. Не нужно считать траекторию самому.

**Где в проекте.** `modules/mission/index.js` — на «ПУСК» из кнопки разлетаются 46 искр.

```js
gsap.to(spark, { duration: 1.5, physics2D: { velocity: 500, angle: 270, gravity: 900 }, autoAlpha: 0 })
```

Угол в градусах: 0 — вправо, 90 — вниз, 270 — вверх (ось Y экрана направлена вниз).

## CustomEase

**Что делает.** Позволяет задать свою кривую сглаживания SVG-путём (его удобно нарисовать в
визуализаторе [gsap.com/docs/v3/Eases/CustomEase](https://gsap.com/docs/v3/Eases/CustomEase)),
а потом использовать по имени, как встроенную.

**Где в проекте.** `src/core/gsap.js` создаёт кривую `liftoff` («взлёт»: медленный старт,
резкий разгон, мягкий финиш). Её использует лайтбокс при раскрытии фото.

```js
CustomEase.create('liftoff', 'M0,0 C0.7,0 0.1,1 1,1')
gsap.to(el, { x: 100, ease: 'liftoff' })
```

## EasePack

**Что делает.** Добавляет необычные кривые: `rough` (рваная, «дрожь»), `slow` (SlowMo:
медленно в середине), `expoScale` (для масштаба).

**Где в проекте.** Кнопка «Пуск» после старта дрожит кривой `rough`.

```js
gsap.fromTo(button, { x: -6 }, { x: 0, duration: 0.8, ease: 'rough({ strength: 3, points: 24, taper: "out", randomize: true })' })
```

`taper: "out"` — дрожь затухает к концу.

## Полезное из ядра GSAP

### `gsap.quickTo` — быстрое «следование»

Для значений, которые меняются очень часто (позиция курсора на каждом `pointermove`),
создавать новый твин на каждое событие расточительно. `quickTo` создаёт **один** твин и
переиспользует его:

```js
const toX = gsap.quickTo(ring, 'x', { duration: 0.35, ease: 'power3' })
window.addEventListener('pointermove', (e) => toX(e.clientX))
```

**Где в проекте.** Кольцо курсора (`modules/cursor/index.js`).

**Подводный камень (на нём споткнулся этот проект).** Любой другой твин того же свойства с
`overwrite: true` **убивает** твин quickTo, и тот перестаёт работать. Так магнитные кнопки
сначала работали только при первом наведении (история бага — в `modules/cursor/README.md`).

### `gsap.context` — уборка

```js
const ctx = gsap.context(() => {
  gsap.to('.a', { x: 100 })
  ScrollTrigger.create({ /* ... */ })
  SplitText.create('.title', { type: 'chars' })
}, rootElement) // селекторы ищутся только внутри rootElement

ctx.revert() // всё убрать и вернуть DOM в исходное состояние
```

Используется во всех DOM-модулях. Это главный инструмент для React/Vue (там есть ещё хук
`useGSAP` из пакета `@gsap/react`, который делает то же автоматически).

### `gsap.ticker`

Общий цикл кадров (см. [02-concepts.md](02-concepts.md#21-кадр-и-цикл-анимации)).
`gsap.ticker.lagSmoothing(500, 33)` (по умолчанию включено): если кадр задержался дольше
500 мс (вкладка была скрыта), время «подрезается», и анимации не прыгают вперёд.

Дальше — [04-architecture.md](04-architecture.md).
